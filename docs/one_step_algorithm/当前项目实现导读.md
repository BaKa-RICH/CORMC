# 当前项目实现导读

本文用于说明当前项目应该怎么读、公式如何落到代码、数据如何流到 plot 和 SUMO replay。它不是论文公式推导，公式细节仍以 `公式整理与分块.md` 为准。

# 1. 当前正式主线

当前项目已经收敛为一条正式主线：

```text
cormc.scenes
  -> cormc.onestep.rolling
  -> 五层 Stage2 summary
  -> cormc.observation
  -> plot
  -> SUMO replay
```

`cormc.scenes` 负责统一场景入口，包括固定场景、随机流场景、场景 ID 和场景配置加载。`cormc.onestep.rolling` 是正式连续滚动主线，会在车辆进入控制区、周期触发或安全触发时进行规划，并输出 Stage2 数据。`cormc.observation` 读取 Stage2 输出，生成标准数据集、图、manifest 和 SUMO replay fidelity validation。

# 2. One-Step 三层组织

`cormc.onestep.kernel` 是单帧算法核心。它只关心一个局部单帧问题：构造 gap、判断可达性、计算协作调整、计算合流时间、评分、选择最优 gap，并生成最优 gap 的轨迹采样。

`cormc.onestep.rolling` 是正式产品主线。它把连续运行中的车辆状态转换成 kernel 使用的局部单帧输入，调用 kernel 做决策，再继续推进车辆、锁定 gap、记录事件和导出 Stage2 summary。

`cormc.onestep.lab` 是算法实验室。它保留单帧参考案例、实验 sweep 和调试能力，不是正式功能入口。新增正式流程时应优先进入 `rolling`，研究单帧公式细节时才看 `kernel` 或 `lab`。

# 3. 公式到代码的对照

| 理论模块 | 代码位置 | 说明 |
| --- | --- | --- |
| gap 构造 | `cormc/onestep/kernel/gaps.py` | 从 `x_targets` 构造候选 gap，并归一化 rear/front。 |
| 可达性筛选 | `cormc/onestep/kernel/reachability.py` | 判断合流车能否在时间窗内同速到达 gap 中心。 |
| 协作调整 | `cormc/onestep/kernel/cooperation.py` | 计算 gap 缺口、相邻容量、可控性分支、投影解和失败原因。 |
| 合流时间与评分 | `cormc/onestep/kernel/timing_scoring.py` | 计算 `t_0`、`t_a`、`t_v`、`t_m`、`C_ego` 和 `J`。 |
| 单帧总评估 | `cormc/onestep/kernel/evaluation.py` | 串起 gap、reachability、cooperation、timing、score，并选出最优 gap。 |
| 轨迹采样 | `cormc/onestep/kernel/trajectory.py` | 对最优 gap 生成合流车、前车、后车和非协作车辆的轨迹样本。 |
| rolling 到 kernel 的局部适配 | `cormc/onestep/rolling/stage2_adapter.py` | 从连续状态构造 kernel 局部坐标、gap 车辆映射和可控性约束。 |
| Stage2 运行与导出 | `cormc/onestep/rolling/stage2_runner.py`、`cormc/onestep/rolling/stage2_analysis.py` | 跑固定场景历史、汇总 Stage2 summary、导出分析产物。 |
| observation / plot / replay | `cormc/observation/` | 从 Stage2 输出生成统一观察数据、plot、artifact bundle 和 SUMO replay。 |

# 4. 数据和产物怎么流动

固定场景从 `cormc.scenes.load_scene_config(...)` 进入。随机流场景由 `cormc.scenes.random_flow` 构造。rolling 主线运行后，核心输出包括：

- `stage2_summary.json`：五层 Stage2 summary，记录场景、触发、gap 选择、生命周期、replay 所需路径等。
- `trajectory.csv`：车辆轨迹行数据。
- `gap_rows.json`：每次触发时 kernel 对各候选 gap 的评估行。

这些输出随后交给 `build_observation_artifact_bundle(...)`。observation 会生成 plot、`stage8_artifact_manifest.json`、`stage8_report.md`、`stage8_sumo_replay/`，并检查 replay fidelity。

# 5. 黄金实验和验收

阶段 9 后的端到端验收入口是：

```powershell
$env:PYTHONIOENCODING='utf-8'
python scripts/phase9_golden.py --compare tests/golden/phase9_expected_fingerprints.json --output artifacts/phase9_regression/check
```

该脚本真实运行 6 个黄金实验：

- `RM-ONESTEP-S05-PLAN-STEP0`
- `RM-ONESTEP-S05-ROLLING-ENTRY`
- `RM-ONESTEP-S07-PLAN-STEP0`
- `RM-ONESTEP-S07-ROLLING-ENTRY`
- `RM-ONESTEP-S07-2MV-ROLLING-ENTRY`
- `RM-ONESTEP-RANDOM-S07-LANE2-RAMP-100S`

每个实验都会从统一场景入口开始，经过 rolling 主线生成 Stage2 输出，再由 observation 生成 plot 和 SUMO replay bundle，最后与黄金指纹基线比对。

# 6. 不要走的旧路

旧 public path 已经关闭，不要恢复兼容 wrapper。新增需求不要从 `cormc.ramp_merge_algorithm`、`cormc.one_step_algorithm`、`cormc.mvs`、`cormc.random_generation`、`cormc.boundary_flow` 或顶层 step 模块进入。

`cormc.legacy` 只作为历史护栏和回归测试抽屉，不是正式项目入口。顶层 `cormc` 只导出 `__version__`，正式调用应进入 `cormc.scenes`、`cormc.onestep.rolling`、`cormc.observation` 和 `cormc.sumo`。
