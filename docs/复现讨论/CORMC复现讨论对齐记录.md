# CORMC 复现讨论对齐记录

本文档用于记录当前阶段对 CORMC 论文复现的共识边界。它不是正式复现计划，也不是论文复习笔记，只用于保证后续实现时主要想法不跑偏。

需要特别说明：`匝道汇入协同驾驶.md` 是第一版参考资料，不是复现计划。后续复现仍以 `docs/papers/P002-2023-Hou-Cooperative-On-Ramp-Merging-Control.md` 对应论文为主，结合讨论中已经确认的取舍执行。

## 第一版目标

第一版先做一个能运行、能看到效果的 Python 仿真版本。运行后应能输出车辆轨迹图 PNG，并能观察 lane 1、lane 2 和 on-ramp 中车辆随时间运动、协同、换道与合流的过程。

第一版不追求和论文结果完全数值一致。优先目标是把论文主链路跑通，保证模型语义清楚、模块边界清楚、后续能继续扩展到更完整的实验。

## 第一版保留范围

- 道路结构保留两条主线车道 `lane 1`、`lane 2`，以及一条 `on-ramp`。
- 混合交通保留 `CAV` 和 `CHV`，其中 `CHV` 再按 compliance rate 分为 compliant 和 non-compliant。
- 保留 APS：每个 MV 独立寻找 lane 2 中的 anticipatory merge position，并选出 CLV / CFV。
- 保留 CUC：lane 2 中需要协同的 CV 在“换到 lane 1”和“继续留在 lane 2”之间做决策。
- 保留 MV 单车合流：动态可接受间隙、边界防撞、正弦轨迹换道。
- 保留主线纵向模型：CAV 使用 cruising + gap-regulating 思路，CHV 使用 IDM。

## 第一版暂不做的内容

- 不做 SUMO 对比。
- 不做严格 MPC 横向轨迹跟踪。
- 不做 CMC platoon 部分，即多个 MV 被视为 platoon 时“只考虑首尾 MV”的规则。
- 第一版暂不做普通主线主动换道，只做 CUC 触发的协同换道。普通主线主动换道后续可以作为可选开关补充。

## 核心实现语义

### 纵向运动

论文中算出加速度的地方，第一版就用实时加速度规则推进车辆状态。

CAV 纵向运动保留 cruising + gap-regulating 的思想：前方无车或间距足够大时靠近期望速度；需要跟驰时根据前车状态、实际间距、期望间距和速度差实时计算加速度。

CHV 纵向运动使用 IDM。compliant CHV 可以听从 CUC 的协同建议，但纵向行为仍按 CHV/IDM 的方式更新；non-compliant CHV 不执行 CUC 建议，继续按自身模型行驶。

### 横向运动

论文中给出正弦参考轨迹的地方，第一版直接按参考轨迹更新车辆横向位置。也就是说，换道和合流时直接让车辆沿参考正弦轨迹运动。

第一版不再额外实现 MPC 或其他轨迹跟踪控制器。这里的重点是复现正弦轨迹对应的位置变化，而不是复现横向控制器如何追踪这条轨迹。

### CUC 决策

CUC 只理解为 lane 2 协同车的决策模块，不把它误解成控制器。它决定被 APS 标记为需要协同的 CV 是换到 lane 1，还是继续留在 lane 2。

CUC 决策应服务于 MV 创建合流间隙。第一版保留其效用选择思想，并保留目标车道安全约束的语义。

CUC 决策之后并不直接更新车辆位置。它只把协同车的 maneuver choice 交给下层模型执行：如果选择换到 lane 1，则该 CV 进入换道模型，横向按正弦参考轨迹运动，纵向仍按其车辆类型对应的纵向模型更新；如果选择继续留在 lane 2，则该 CV 不发生横向换道，继续通过纵向模型调整速度和间距。论文原版在正弦轨迹之后使用 MPC 做横向轨迹跟踪，第一版复现去掉 MPC，直接按参考轨迹更新横向位置。

### CMC 合流

CMC 用于 MV 的单车合流过程。MV 先根据动态可接受间隙判断当前 CLV / CFV 之间的实际 gap 是否可接受，同时考虑边界防撞约束；满足条件后，MV 沿正弦轨迹并入 lane 2。

第一版不实现多个 MV 组成 platoon 后只考虑首尾 MV 的规则。每辆 MV 独立处理 APS 和合流。

## CPID 的处理口径

CPID 属于 CAV 纵向 gap-regulating 的一种加速度模型，不是横向 MPC，也不是轨迹插值方法。

CORMC 论文给出了 CAV gap-regulating 的 CPID 公式，但本篇参数表没有给出完整 PID 增益。第一版不让 CPID 成为复现障碍：实现时可以保留 CPID 形式或等价的 gap-regulating 加速度规则，并将相关参数配置化。

默认参数可参考论文引用前作 DCPID 的 Group 2 参数：

```text
Kpx = 8
Kix = 0
Kdx = 10
Kpv = 5
Kiv = 0
Kdv = 0
```

这些参数只作为第一版可运行默认值，不代表数值完全复现。后续实验阶段可以继续调参或根据更多文献材料修正。

## 待后续继续讨论

小场景先跑通是正确方向，但现在不提前确定小场景参数。小场景需要在论文算法时序、状态更新顺序、APS/CUC/CMC 交互关系梳理清楚后再单独设计，并在采用前说明清楚它要验证什么。

第一版代码结构应保留后续消融实验的可能性，例如预留 APS 和 CUC 的开关，但第一版不强求完整复现论文表格和大规模统计实验。
